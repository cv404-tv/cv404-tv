# 云谷404 × 合办方｜第二期 Jev 黑客松提案（讨论稿）

更新：2026-09-23。供合办方讨论，流程、评审和分工均为建议。最新海报确认活动时间为 **9 月 27 日 10:00–20:00**、地点为**云谷中心 B2-3F 活动区**，**免费报名、限 30 名**，并列出云谷404、杭州AI工坊、杭州黑客与画家和 YOUR SPACE。海报承诺比赛提供模型使用额度，具体规则待公布；奖项和伙伴分工仍待确定。现有活动页继续征集报名意向。

## 活动主张

**主题：让 AI 做出下一步决定。**用 Jev 为一个真实场景做关键判断，再让程序采取行动。参赛作品需要展示“输入 → 判断 → 动作”，也要说明信息不足、判断不确定或 API 失败时怎么办。

延续第一期“做出能体验的作品、现场演示”的气质，第二期聚焦三个方向：智能分流、Agent 的下一步、会判断的工作流；也欢迎符合主题的自由命题。Jev 适合定义清楚的 Choice、Score、Noul 问题；`confidence` 不能直接当作正确率，阈值要按场景风险测试。技术依据见 [TypeSafe 官方文档](https://docs.typesafe.ai/introduction)、[问题类型](https://docs.typesafe.ai/primitives)和[置信度说明](https://docs.typesafe.ai/confidence)。

## 建议规模与规则

| 项目 | 提议 |
| --- | --- |
| 时间 | **2026-09-27 10:00–20:00**，共 10 小时 |
| 形式 | 云谷中心 B2-3F 活动区线下共创＋现场演示；旁听席待定 |
| 规模 | 最多 30 名参赛者；拟组 8–12 队，每队 1–3 人 |
| 对象 | 开发者、设计师、产品人及有具体场景的探索者 |
| 作品 | 可操作 Demo、至少一次真实 Jev 调用、约 10 条自建测试样例，以及一种不确定或失败时的回退方式 |
| 赛前基础 | 可使用已有项目和 AI 编程工具；说明已有部分，评审关注活动期间完成的判断链路 |
| 奖项 | 建议设最佳作品、最佳判断设计、观众选择；奖品与数量待预算确认 |

参赛者自行保管个人 API Key。最新海报已承诺比赛提供模型使用额度；提供的模型、额度获取与使用规则仍需明确。活动伙伴以最新海报为准；除非另行确认，不使用“TypeSafe 官方活动/赞助”表述。

## 当天流程（10:00–20:00）

| 时间 | 环节 |
| --- | --- |
| 10:00–10:30 | 签到、开场、介绍主题和规则 |
| 10:30–11:00 | Jev 最小示例、认识队友、确定题目 |
| 11:00–12:30 | 第一轮开发：先跑通输入到动作 |
| 12:30–13:15 | 午餐与交流 |

若实际超过 12 队，需设置展台初筛或缩短单队展示时长，不能直接挤占评分与结束时间。

## 评审建议

统一按 100 分评审：问题与产品完整度 **30**、Jev 使用是否恰当 **25**、测试与回退 **25**、演示表达 **20**。评委独立评分，观众票单列。作品可以用模拟数据演示界面，但不能把模拟响应说成真实 Jev 调用；全场 API 故障时统一改用赛前真实调用记录作为证据，并说明验证边界。

## 合办方式与待审批事项

建议云谷404负责活动内容、报名页与报名管理、参赛手册和作品整理；合办方根据资源牵头场地与现场运营、嘉宾/评委邀约及联合传播。主持、技术支持、摄影、餐饮和奖品由双方在预算内分配负责人。对外名称、视觉和发布内容由双方共同确认。

| 需要共同确认 | 审核重点 |
| --- | --- |
| 现场执行与席位 | 确认 10 小时场地使用所需的网络、电源、投屏与最多 30 个参赛席位 |
| 报名与确认 | 报名截止、候补、组队办法；现有站内审核**不会自动发送通知**，到场确认需人工跟进 |
| 模型额度与使用 | 比赛提供模型使用额度；确认具体模型、领取方式、使用范围、成本上限与故障时的统一规则 |
| 嘉宾与奖项 | 评委人数、回避方式、奖项及奖品预算 |
| 分工与预算 | 场地、餐饮、物料、摄影、技术支持、宣传的负责人及费用承担方 |
| 对外发布 | 合办方名称、标识使用、摄影和作品公开授权 |

建议完成剩余事项后，再把活动页从“报名意向征集”更新为正式招募。预算按场地、餐饮、物料、奖项、API/技术支持和摄影逐项报价，另留 10%–15% 机动空间。活动结束后可发布经作者同意的作品集，并在两周内组织一次轻量复盘。
