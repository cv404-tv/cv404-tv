404 BUILD / VOL.001 / 创作指南

先做出一个
能被体验的版本。

这是云谷404第一期迷你黑客松的参赛指南。我们围绕小红书小工具，完成现场开发、演示、投票和上传。

第一期活动资料存档。平台规范可能更新，当前限制与上传要求请以小红书官方文档和后台为准。

01 / 带什么作品来？

作品不需要庞大。围绕一个明确的问题，完成一个可以操作的核心页面，先跑通一条完整流程。

  • 一个可以完整体验核心流程的作品；
  • 一个符合小红书小工具规范、可上传的 ZIP 包；
  • 一段能讲清问题、并完成真实操作的现场演示。

02 / 现场怎么进行？

  1. 认识彼此。自愿介绍，每人最多30秒：你是谁、你在做什么、今天想做什么。
  2. 开始 Coding。个人参赛，先实现核心操作，再完善移动端适配和视觉细节。
  3. 上台演示。一句话说明作品解决什么问题，然后完整操作一次。
  4. 互相投票。看得懂、跑得通、记得住，把票投给你希望继续看到的作品。
  5. 发布与合影。保留作品和演示入口，把它作为认识新朋友的名片。

03 / 开发时，记住这几件事。

第一期使用离线 H5 小工具交付方式：资源放进包里，使用相对路径，适配手机安全区。不要依赖远程接口、CDN 或在线字体。

ZIP 根目录直接放 index.html；脚本放在外部 JS 文件中；使用事件监听完成交互。具体包大小、Bridge 能力及容器限制，请在发布前核对官方要求。

打开小红书创作服务平台 ↗

04 / 演示之前，走完一遍。

  • 入口能打开，第一眼知道作品做什么；
  • 关键流程能从头到尾，结果页能重试或返回；
  • 连续点击、快速切换不会卡住；
  • 手机上没有横向溢出，文字和按钮没有被遮挡；
  • 已在平台预览和至少一台真机上体验核心流程；
  • 已经备份最终 ZIP，并排练过一次演示。

自动校验和普通浏览器测试，不能代替真实容器验证。把最后一点时间留给测试和演示。

先做出来，讲清楚，再发出去。
